# ADR-001: Standardized Documentation Hierarchy (docs/)

## Status
Accepted

## Context
AI coding assistants (Google Antigravity, Gemini CLI, Claude Code) and human developers need an open, standardized, discoverable documentation hierarchy. Storing project architecture exclusively in hidden directories (e.g. `.agents/context/`) obscures system visibility in standard IDEs and git web interfaces.

## Decision
Adopt a standard `docs/` knowledge hierarchy in {{PROJECT_NAME}}:
- `docs/architecture/`: System design, database schemas, and API route contracts.
- `docs/development/`: Operational guide, developer workflows, and architectural invariants.
- `docs/decisions/`: Architectural Decision Records (ADRs).

## Consequences
- Single source of truth for architectural documentation.
- Native visibility on GitHub, GitLab, and markdown document viewers.
- AI agents can selectively inspect relevant documentation files without token bloating.
